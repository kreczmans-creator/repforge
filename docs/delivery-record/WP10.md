Measurement entry for body weight and twelve circumference sites (neck, chest, waist, hip; left/right thigh, calf, biceps, forearm); date picker and validation; history with edit and delete; trend charts with axes, units and selectable ranges; comparison between two dates or periods; progress summary; CSV export; measurement data in the existing full JSON export/import.
Requirements: D04 BCM-001..BCM-009, UXD-009 (charts). D06 acceptance: BCM P1 criteria pass; chart renders correctly for 1, 2 and 100 points; export opens in a spreadsheet. D06 verification: widget and golden tests for the chart; unit tests for comparisons.
Out of scope: body measurement goals and wider analytics (WP 11); per-domain CSV beyond measurements (DAT-006 other domains); published JSON schema (DAT-005(2)); imperial units (OQ-02 open; kg and cm only).

## Date and time semantics (assumptions, recorded)
- `recordedAt` is an instant stored as UTC; ranges, "today", "future" and comparison dates use the **local calendar date** of that instant. `dayStartHour` (diary day, OQ-18 open) is **not** applied to measurements: a measurement belongs to the calendar date it was taken. Tests pin a non-UTC time zone.
- An entry taken "today" defaults to the current time; a back-dated entry defaults to 12:00 local on the chosen date (editable).

## Owner decisions (2026-11-05, D04 §7)
- **D1 approved with correction**: trailing 7-calendar-day average ending on each day with an entry; daily means first; a trend point needs **at least three individual readings** in the window (not three distinct days); raw readings visible.
- **D2 approved**: `share_plus` + `file_selector` behind a platform-neutral port; ADR-0011 accepted; compatibility verified before implementation.
- **D3 approved**: minimal Settings backup screen on the existing `DriftBackupRepository`; date and record counts before restore confirmation; invalid or newer-format files rejected without change.
- **D4 approved**: period means with the reading count per period; for a date without an exact reading, the nearest earlier and later readings are shown with their dates and the user chooses — no silent substitution.
- **D5 approved**: `date, type, value, unit`; UTF-8; header row; one row per reading; ISO 8601 local date-time with UTC offset.
- Authority: stages 1–2 continue; stage 3 after ADR-0011 and the file-output implementation have been reviewed; no schema migration without evidence.

## Decisions requested at stage 0 (history; decided above)
- **D1 — BCM-006 smoothing (D04 labels the method a proposal).** Ambiguities in "7-day moving average over days with entries": per-entry or per-day mean; window of 7 calendar days or of the last 7 days that have entries; trailing or centred. **Recommendation:** trailing window of 7 calendar days ending on each day that has an entry; first average each day's entries, then average those daily means; draw a trend value only when the window holds at least 3 days with entries (D04 "fewer than 3 entries" read as days with entries); raw entries always drawn. Implemented as one pure function so another choice changes one place. Until decided, the line is labelled "7-day average (proposed method)".
- **D2 — file output for CSV and backup (new platform capability).** The app has no way to hand a file to the user. **Recommendation:** ADR-0011 (proposed, `docs/adr/ADR-0011-file-export-and-import.md`; `share_plus` 13.3.1, `file_selector` 1.1.0): `share_plus` (system share sheet: save to Files/Drive, email) for exports and `file_selector` for choosing a backup to restore, both behind a Flutter-free port in `lib/data/platform/` with a fake for tests (ADR-0006 standing constraint), pinned to releases at least two weeks old. Stage 3 waits for this decision; stages 1–2 do not depend on it.
- **D3 — backup export/import screen.** D06 WP 10 scope and the WP 3 record allocate the export/import screen to WP 10; the owner's instruction says to reuse the existing mechanism. **Proposed:** a minimal screen in Settings using the existing `DriftBackupRepository` only — export file; restore showing record counts and backup date with confirmation; invalid or newer files rejected without change (DAT-004(1)(2)). DAT-005(2) (published schema) and DAT-006 for other domains stay out of scope. Confirm or remove from WP 10.
- **D4 — "compare two periods".** **Proposed:** for dates, the reading on (or nearest to) each date; for periods, the mean of the readings in each period with the count shown. Confirm.
- **D5 — CSV columns.** **Proposed:** `date` (ISO 8601 local date-time with UTC offset), `type` (site name, e.g. "Left thigh"), `value`, `unit` (kg or cm); UTF-8 with header row; one row per reading. Confirm.
